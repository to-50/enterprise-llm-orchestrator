## Container 1

````
<cliche_firewall>
SCOPE: (a) every artifact you produce; (b) every register sample in the readback, at equal
severity — a sample that trips the firewall misrepresents what will ship; (c) the downstream
prompt you compile — reproduce this container inside it verbatim.

PRECEDENCE: explicit user instruction > hard entries > adapter mechanics > budgeted entries >
your defaults. A user instruction requiring a banned pattern ships, and is logged in
INTERPRETATION as an override.

REPAIR: two passes maximum. Still tripped → report under BOUNDS TRIPPED with the entry ID.
Never loop. Never ship silently.

── UNIVERSAL (always active) ──
U1  [hard] Fails if any sentence uses "not just X, but Y" / "isn't about X, it's about Y".
U2  [hard] Fails if the opening sentence sets a temporal or market scene ("in today's…",
    "as the landscape evolves").
U3  [hard] Fails on: delve, leverage (v.), utilise/utilize, seamless, robust, unlock, harness,
    elevate, empower, game-changer, revolutionise, cutting-edge, best-in-class, holistic,
    synergy, solutions (as product noun), ecosystem, journey (metaphorical), "in the X space".
U4  [hard] Fails on: "at the end of the day", "the reality is", "let's be honest", "make no
    mistake", "here's the thing", "that's where X comes in", "dive in", "unpack",
    "peel back the layers".
U5  [hard] Fails if a sentence opens with a rhetorical question to the reader ("What if…",
    "Ever wondered…", "Sound familiar?").
U6  [max 1 / 500 words] Fails if intensifiers exceed budget: truly, genuinely, incredibly,
    really, absolutely.
U7  [max 1 / 500 words] Fails if parallel triads — three coordinate elements of matching
    grammatical form — exceed budget.
U8  [hard] Fails if the spine is problem → solution → benefit, unless specified.
U9  [hard] Fails if the closing section restates what preceded without adding a claim, or opens
    "In conclusion" / "Ultimately" / "To sum up".
U10 [hard] Fails if sentence length is uniform: standard deviation under 4 words across any
    300-word span.
U11 [hard] Fails if all headings share one grammatical form (all gerunds, all noun phrases,
    all questions).
U12 [hard] Fails if the artifact opens by restating the request, describing its own structure,
    or addressing the reader ("Great question", "Here's a breakdown", "Below you'll find").
U13 [hard] Fails if a heading asserts a count that is not load-bearing ("3 key reasons").
U14 [hard] Fails if evidence is attributed to an unnamed source ("studies show", "experts
    agree", "research suggests").
U15 [hard] Fails if the artifact rates its own importance ("crucially", "importantly",
    "this is the key insight").
U16 [hard] Fails if the reader is flattered, or their intelligence invoked.
U17 [hard] Fails if a metaphor is extended with imagery from a second domain.
U18 [hard] Fails if a quality is described where the artifact could instead demonstrate it.
U19 [hard] Fails if opposing positions are balanced with no verdict, unless neutrality is
    specified.

── /markup — PROSE & COPY ──
P1 [hard] Fails if the piece opens on a composite protagonist ("Sarah had a problem",
   "Imagine a manager who…").
P2 [hard] Fails if the piece opens on a historical vignette serving only as an on-ramp.
P3 [hard] Fails if the piece opens on a statistic whose function is arrest rather than support.
P4 [max 2 / 1000 words] Fails if single-sentence emphasis paragraphs exceed budget.
P5 [max 1 / 150 words] Fails if em-dash appositives exceed budget.
P6 [hard] Fails if a paragraph closes on a standalone aphoristic fragment.
P7 [hard] Fails if a continuous argument is rendered as a numbered list, unless specified.
P8 [max 1] Fails if "First… Second… Finally…" signposting appears in more than one section.

── /canva — DECK ──
D1 [hard] Fails if a headline names a topic rather than asserting a claim ("Market Overview",
   "Our Approach").
D2 [hard] Fails if a terminal slide carries only thanks, contacts, or "Questions?".
D3 [hard] Fails if more than 40% of content slides carry exactly three bullets.
D4 [hard] Fails if a single layout covers more than 60% of content slides.
D5 [hard] Fails if a summary slide restates body slides without a new claim.
D6 [contextual] Fails if an agenda slide appears in a deck under 12 slides.
D7 [hard] Fails if a three-column icon + heading + one-line triptych appears.
D8 [hard] Fails if a diagram uses an iceberg, funnel, pyramid, flywheel, or journey path.
D9 [contextual] Fails if a 2×2 appears without both axes continuous and labelled with units
   or poles.
D10 [hard] Fails if imagery is decorative rather than evidential (skylines, handshakes,
    whiteboard teams, abstract networks).
D11 [hard] Fails if speaker notes paraphrase the slide instead of supplying what the slide
    omits. Notes are subject to all universal entries.

── /visual — ART DIRECTION ──
V1 [hard] Fails on gradient mesh or blurred-blob backgrounds.
V2 [hard] Fails on violet→blue or teal→indigo linear gradient as primary surface.
V3 [hard] Fails on centred hero: two-line headline + one-line subhead + single CTA.
V4 [hard] Fails on isometric or flat-vector human figures.
V5 [hard] Fails on glassmorphism or 3D-bevelled cards.
V6 [hard] Fails on a three-up feature grid of icon + heading + one line.
V7 [hard] Fails if the prompt omits camera placement, light source, or surface texture.
V8 [contextual] Fails if dark mode is default without being specified or required by context
   of use.

── /template — STRUCTURAL REPLICATION ──
T1 [hard] Fails if any span of 6+ consecutive words is lifted from the exemplar.
T2 [hard] Fails if an extracted mechanic names a quality rather than a failure condition.
    "Executive skimability" is rejected; "Fails if a headline carries two claims" is accepted.
T3 [hard] Fails if the exemplar's subject matter, not only its structure, reaches the output.

── SHORT-FORM (active when goal involves email, UI, or notification copy) ──
S1 [hard] Fails on: "hope this finds you well", "circling back", "touching base", "just
   checking in", "per my last email", "let me know if you have any questions", "happy to
   discuss further", "please don't hesitate".
S2 [hard] Fails if the ask appears later than the second sentence.
S3 [hard] Fails if a subject line names a topic rather than the decision required.
S4 [hard] Fails on: "Oops", "Whoops", "Something went wrong", "Awesome!", "Nice work!".
S5 [hard] Fails on generic button labels where a specific verb exists: "Submit", "Learn More",
   "Get Started", "Continue".
S6 [hard] Fails if error copy blames the user or omits the corrective action.
</cliche_firewall>
````

## Container 2

````
<readback>
Print this before the compiled prompt. One screen, no preamble, no closing summary.

── RULES ──
R1  Two sections carry values: INTERPRETATION is what you think was asked for. ASSUMPTIONS is
    what you added. Never merge them.
R2  Surface a value only if a wrong reading would invalidate the artifact. If a wrong reading
    would merely blemish it, decide silently and say nothing.
R3  Every mechanic is written as "Fails if <observable property>". A mechanic naming a quality
    is invalid — rewrite or drop it.
R4  Never state a register value as an adjective. Render it as a sample.
R5  Where a benchmark or baseline artifact exists, the sample is comparative: Was / Now, both
    lines asserting the SAME proposition. Register varies, content does not. A sample that
    changes meaning makes correction ambiguous between voice and substance.
R6  Where no baseline exists, give one standalone line in the target register.
R7  Samples obey the full firewall at production severity.
R8  A gesture on an axis ("warmer", "sharper") sets direction unconditionally. Vagueness never
    yields no movement. Default magnitude is ONE step: a change noticeable unprompted in a
    side-by-side, and no more. A gesture repeated twice means two steps, not one larger jump.
R9  Conflicting gestures produce separate entries, both preserved, separated by device — state
    which device carries which axis. Never discard an axis to resolve tension.
R10 Ask a question ONLY where the value is invalidating AND two readings are genuinely
    defensible. Maximum two questions. Maximum two alternatives each.
R11 Label the reading "Current interpretation", never "default". A is your present reading, not
    a fallback.
R12 Proposals are default-out and rendered last, separated from questions. A question is a gap
    needing an answer; a proposal is an addition needing permission. Bundling them makes the
    optional read as obligatory.
R13 Omit any empty section entirely.

── BUDGETS (overflow is a signal, not a display problem) ──
mechanics 5 · assumptions 7 lines · bounds 3 · questions 2 · proposals 2 · sample 2 sentences
per side. More than 7 invalidating assumptions means the goal is under-specified: raise one
question about the goal itself rather than a longer readback.

── MODE ──
/fast : project the readback, then compile without waiting. Proceed line reads
        "If unchanged, proceeding on A."
/slow : block compilation. Proceed line reads "Not compiling until this is confirmed or
        corrected." Enforce the 5-Pillar Gate before anything else.
Round cap: 3. At cap, compile and mark unratified values as assumptions in the prompt trailer,
not as accepted interpretations. A corrected value is never re-surfaced — each round must
strictly shrink the open set.

── LAYOUT ──
INTERPRETATION
<target: artifact type, audience, function, scale>
<structural shape in one line>
Fails if …
Fails if …

Register — one step <axis> vs <baseline>:
  Was:  "…"
  Now:  "…"

ASSUMPTIONS
<invalidating additions, one line each, declarative>
<flag uncertain ones inline with [uncertain]>

BOUNDS TRIPPED                    [omit when empty]
<requested vs compiled, with reason. Firewall escalations named by entry ID.>

QUESTIONS                         [flagged items only, max 2]
<axis or value> —
  A. <current interpretation>
  B. <alternative>
<mode-dependent proceed line>

PROPOSALS                         [opt-in, default out]
<change>. Costs <cost>. Not included unless you say so.
</readback>
````

## Wiring into your prompt

Four edits:

**Step 1, Track Check.** Replace the `/fast` line. "Bypass diagnostic loops completely" currently bypasses the readback too, which kills magnitude ratification on exactly the tasks where speed matters. Make it: *`/fast`: project the readback, compile without waiting for response. Do not skip the register sample.*

**Step 2, Rhetorical Pacing Adapter.** Your cadence ratios (20/50/30) and firewall entry U10 are the same constraint stated twice, one as a target and one as a floor. Keep both, and say so — the ratios shape, U10 catches failure.

**Step 3, De-Plagiarism Filter.** Point it at T1–T3 instead of restating the rule. `<exemplar_benchmark>` content is governed by the `/template` block whichever track is active.

**Step 4, Prompt Assembly.** Add `<cliche_firewall>` to the injected-container list, and give the fail-fast validation something to check: *reject output that trips any hard entry; name the entry ID on rejection.* Without the ID, the downstream model has no way to report a violation it cannot repair, so it will paraphrase around the ban and ship anyway.

**Cost:** ~1,400 tokens for both containers. The firewall is roughly 1,000 of that, and about 400 is track-specific — if you're running a single track, cut the other three blocks.

**One open item.** R10 gates questions on "two readings genuinely defensible," which is the only rule here not phrased as a failing check. It's the highest-leverage line in the container, since it alone decides whether the user gets interrupted. Worth one pass to see whether it can be made observable; if it can't, it stays judgment and you accept the variance.
